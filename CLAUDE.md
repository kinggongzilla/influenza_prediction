# Influenza Prediction Pipeline

All commands run from `forecast_pipeline/`.

## Architecture

Chronos-2 (patch-based transformer, quantile regression loss) fine-tuned on WHO ILI/ARI surveillance data from 89 countries (73 appear on the world map, including the UK as a single polygon combining the England/Scotland/N. Ireland series; the remaining 14 small-island territories are only reachable via their country pages). Produces probabilistic 4-week-ahead forecasts with prediction intervals.

## Key Data Concepts

- **ILI vs ARI**: Countries report Influenza-Like Illness (ILI) or Acute Respiratory Infection (ARI). Some switched mid-stream (Italy: ILI->ARI in late 2025). Combined CSVs have a `DataType` column (0=ILI, 1=ARI).
- **Parallel-reporting guard**: a few countries report ILI and ARI *simultaneously* at very different scales (e.g. Russia: a tiny sentinel ILI network, median ~70/wk, next to national ARI totals, median ~280k/wk). Interleaving the two scales in one series is unusable (zero-ILI weeks get filled with 100k+ ARI values). `extract_combined_data()` therefore keeps only the larger-scale indicator when both are reported in parallel for >=26 weeks and the positive-value medians differ by >10x, provided the winner itself passes the quality-screen floors (>=156 weeks, >=4 years). As of 2026-08-27 this flipped 19 countries (all to ARI): Belarus, Belgium, Colombia, Czechia, Estonia, Finland, Kazakhstan, Lithuania, Mexico, Netherlands, Paraguay, Peru, Russian Federation, Slovakia, Spain, Ukraine, and the UK components England/Scotland/N. Ireland (so the combined GB map series is now the sum of three ARI series).
- **Extracted CSVs**: `data/extracted_data/<Country>_combined.csv` with columns `Time,Cases,DataType`. Prefer `_combined.csv` > `_ili.csv` > `_ari.csv` in all file lookups.
- **training_countries.json**: Auto-generated by `prepare_finetune_data.py --assess_only`. Contains the list of qualifying countries and their data types. This is the single source of truth for which countries are used.
- **Quality thresholds**: MIN_WEEKS_NONNAN=156, MIN_YEARS_COVERAGE=4, MAX_NAN_PCT_SPORADIC=50%, MIN_MEDIAN_NONZERO=20 (in `prepare_finetune_data.py`).

## Unified `--covariates` Flag

Three scripts share the same `--covariates` interface:

| Script | Available covariates |
|--------|---------------------|
| `scripts/prepare_finetune_data.py` | data_type, hemisphere, week_of_year, weather, neighbors |
| `run_evaluation.py` | data_type, hemisphere, week_of_year, weather, neighbors |
| `scripts/eval_influcast_pairwise.py` | data_type, hemisphere, week_of_year, weather |

Behavior:
- Flag omitted: `prepare_finetune_data.py` uses ALL covariates; `run_evaluation.py` and `eval_influcast_pairwise.py` use NONE
- `--covariates` (no args): no covariates (target only)
- `--covariates data_type week_of_year`: only those two

Models trained with covariates can be evaluated without covariates. Simple/static covariates (hemisphere) may help at inference; complex covariates (weather, neighbors) tend not to help. Testing both with and without covariates at inference is recommended.

## Shared Utilities (`scripts/`)

- **data_loader.py**: `load_time_series_data()`, `load_data_type_indicator()`, `clean_zeros_to_nan()`, `trim_leading_artifact()`. Central place for data loading and cleaning.
- **weather_fetcher.py**: `fetch_weather_data()` (Open-Meteo API), `get_country_coordinates()`, `aggregate_weather_to_weekly()`, `normalize_weather_features()`. Rate-limited with retry backoff.
- **country_neighbors.py**: `get_neighbors()` returns geographically neighboring countries.
- **chronos_inference.py**: Low-level inference wrapper.
- **UK handling**: WHO reports England/Scotland/N. Ireland (and Wales) as separate series, but the site shows a single **United Kingdom**: `generate_country_details.py` sums the available component series into `details/GB.json` (Wales excluded — separate WHO series; intervals are the sum of component intervals), and `generate_map_data.py` colors the single GB base polygon (ISO numeric 826) from that combined detail. The UK sub-region map overlay (OSM `uk_subregions.json`) was removed — at world-map scale the sub-regions were too small to read and Scotland's staleness made the UK look dead. The 3 sub-region models are still trained; only their display was merged.

## Weather System

- **API**: Open-Meteo Historical Weather (free, rate-limited to ~0.5 calls/sec)
- **Cache**: `data/weather_cache/{lat}_{lon}_{start}_{end}.parquet` (daily data: temp_mean/max/min, humidity_mean/min)
- **Prefetch**: `scripts/prefetch_weather.py` reads `training_countries.json`, checks freshness (14-day threshold), fetches missing or extends stale caches incrementally (only fetches the missing tail, then merges parquet files)
- **Cache lookup**: `_find_best_weather_cache(lat, lon, start, end)` exists in both `prepare_finetune_data.py` and `run_evaluation.py` (duplicated but identical logic)

## Country Name Mapping

Several scripts have a `COUNTRY_NAME_MAP` dict that maps WHO country names to shorter forms for weather/coordinate lookup (e.g. "Türkiye" -> "Turkey", "Russian Federation" -> "Russia"). These are duplicated across `prepare_finetune_data.py`, `prefetch_weather.py`, and `run_evaluation.py`.

## Influcast Benchmarking

`scripts/eval_influcast_pairwise.py` compares against Italian Influcast models using pairwise relative WIS (Cramer et al., 2022).

- Seasons defined in `SEASONS` dict: 2023-24 (ILI), 2024-25 (ILI), 2025-26 (ARI)
- Downloads forecasts from `github.com/Predizioni-Epidemiologiche-Italia/Influcast`
- Uses its own data file: `data/influcast_italy_national.csv` (year_week, incidence)
- Cache: `data/influcast_cache/`

## Pipeline Order

1. `update_who_data.py --backup` (download WHO data)
2. `enhanced_extract_country_data.py --all` (extract per-country CSVs)
3. `scripts/prefetch_weather.py --refresh_stale` (optional, for weather covariate)
4. `scripts/prepare_finetune_data.py --covariates ... --exclude_countries "Thailand,Belarus,Colombia"` (quality scan + training samples)
5. `scripts/finetune_chronos.py --output_dir models/...` (fine-tune)
6. `run_all_country_inference.py --model_path ... --countries_file data/training_countries.json` (inference)
7. `generate_map_data.py` + `generate_country_details.py` (frontend JSON)
8. `cd ../frontend && npm run dev` (serve dashboard)

## Evaluation

- `run_evaluation.py`: Rolling WIS evaluation (H1-H4 averaged) for any country/season. Uses naive random-walk baseline (Fiandrino et al., 2025). Supports `--quiet` for clean sorted table output. Plots to `results/evaluation/plots/`.
- `scripts/eval_influcast_pairwise.py`: Head-to-head vs Influcast participants (Italy only).
- `scripts/run_ablation.py`: Full covariate ablation (all 2^5 combinations + zero-shot baseline). Supports `--nocov_eval` to evaluate all models without covariates, `--eval_only`, `--collect_only`, `--all_countries` to eval on all training countries instead of default 7, `--experiments 0,3,11` to run specific experiment IDs.

## Frontend

Next.js app in `frontend/`. Reads JSON from `frontend/public/data/`. World map + per-country detail pages. Branding: header logo `public/images/logo.svg` (globe + epidemic curve); favicon is `src/app/icon.svg` (same design; the default `favicon.ico` was removed). The UK renders as the single GB base polygon, colored from the combined England/Scotland/N. Ireland series (see "UK handling" in Shared Utilities); Wales is not included.

The map JSON (`influenza_status.json`) is an object: `{generated_at, default_week, weeks, countries}`. The map's default view is the **Nowcast**: `default_week` is always the calendar's current ISO week (labeled by its Monday). Each fresh country's top-level `value`/`zscore`/`score`/`status` are for that week: its **actual** if one has been reported (`value_source: "actual"`) — the WHO feed fills that in during the week as countries report — otherwise the **forecast** for it (`value_source: "forecast"`; displayed forecasts are clamped at zero); the map tooltip says **Nowcast: Actual**/**Nowcast: Predicted** accordingly. The selector always offers the nowcast week plus the next 4 (`weeks` = 5 entries, "Nowcast" first) — the dashboard's 5-week look-ahead. Each country's `forecast_weeks: [{date, value, zscore, score, status}]` holds only the future weeks within 8 weeks (`FORECAST_HORIZON_DAYS`) of that country's own latest data — matched to the 8-week detail-page forecast window (and the 8-week staleness cutoff) so the selector stays covered even when the WHO feed lags the calendar; always forecasts, clamped at zero — the model mean can dip slightly negative on low-activity series); picking a week re-colors the map from that week's per-country z-score, and countries whose horizon doesn't reach it go gray (a week beyond every country's horizon would show an all-gray map). Detail JSONs (`details/<CODE>.json`, 87 total — one per displayed country, the three UK components combined into GB; 73 on the map) carry `points[]` with `historical`/`forecast`/quantiles per week. The detail page's Range selector (1Y / 3Y / 5Y / All, **3Y is the default**) shows the last N weeks of *history* plus the near-term 8-week forecast, anchored to the last historical week; `All` shows the full series including the whole forecast horizon. The prediction-interval bands are labeled and toggleable: **90% PI** (`lower`/`upper`, q0.1–q0.9) and **50% PI** (`lower_50`/`upper_50`, interpolated midpoints) each have a checkbox (both on by default). Since a recharts Area fills from its line down to its baseline, each band is a colored Area plus a white "eraser" Area beneath it, all pinned to the plot bottom with an explicit `baseValue` and numeric y-domain (recharts' default baseline snaps to 0 when 0 is in the domain, which would cut off the lower half of any PI that straddles zero); fills are truly opaque (`fillOpacity={1}` — recharts v3 otherwise defaults fill-opacity to 0.6) so every region between the four boundary lines carries exactly one color: pale-blue 90% band, darker-blue 50% band, symmetric about the mean; every Area also gets an explicit `activeDot` (recharts otherwise colors a boundary dot with the Area's own fill — the white eraser used to produce a blank dot); the Legend uses custom `content` (a whitelist) because recharts v3 dropped the `payload` prop and unnamed eraser Areas would otherwise show as stray "lower"/"lower_50" legend entries. The Tooltip is also custom (`ChartTooltip`): it shows the intervals as **ranges** ("90% prediction interval: 27 – 195") built from the paired lower/upper values, skips rows whose value is null (historical weeks show only observed cases), and hides the draw-only eraser series. The methodology page renders `data/country_list.json` (written by `generate_map_data.py`) as a linked, expandable table of every trained country, including the 14 small-island territories that can't be colored on the map. The map itself is pinch-zoomable on touch devices (`MapChart.tsx`): at rest `touch-action: pan-y` keeps one-finger page scrolling native; once the user pinch-zooms in (`touch-action` flips to `none`) one-finger drags pan, up to 8×, with +/−/reset buttons and a zoom hint (`md:hidden`); desktop stays a static map (mouse events are ignored) so page wheel-scroll is never hijacked. Small-country tap targets are the reason for the zoom — tiny islands are hard to tap at the fitted 800×420 scale.

**Current-activity rule**: the dashboard's default view (the **Nowcast** — the calendar's current week) shows each country's **actual** value for that week if one has been reported, otherwise its **forecast** for it. The detail pages show 8 weeks of forecast, so a country whose last data point is less than 8 weeks old always has a nowcast value; at or beyond that gap (`STALE_AFTER_DAYS = 56` in `generate_map_data.py` / `generate_country_details.py`) it is marked `stale`: gray on the map (tooltip shows last-update date), and its detail JSON has all forecast fields nulled (history only, with a banner). This prevents e.g. a country that stopped reporting in 2022 from showing a 2023 forecast as current activity. Seasonally-reporting countries (e.g. Italy: winter season only, ILI→ARI switch in Oct 2025) go gray during their summer break — that is intended.

## Deployment (Cloudflare Pages)

The site is 100% static at runtime (all data is client-side `fetch` from `/data/`), so it deploys as a static export to **https://influenza-dashboard.pages.dev**:

- `next.config.ts` adds `output: 'export'` **only when `STATIC_EXPORT=1`** is set. Normal builds (used by local `next start -p 3000`) are unaffected.
- `/country/[id]` is a server-page wrapper that calls `generateStaticParams()` (enumerates ISO2 codes from `public/data/details/`) and renders the client component `CountryDetails.tsx`. Required for static export of the dynamic route.
- **`auto_update.sh` step 6** does the whole deploy after JSON generation, so the **daily 09:00 cron** keeps the live site in sync hands-off. WHO syncs the feed continuously (roughly daily), so the run is daily; a WHO-file-unchanged day is detected by a sha256 comparison in the step-2 guard and skipped entirely (no pipeline work, no deploy). Build/deploy failure → ERR trap aborts before any swap, so the last good version stays live.
- Auth: API token in `~/.cloudflare_api_token` (chmod 600; created from the "Edit Cloudflare Workers" template) or the `CLOUDFLARE_API_TOKEN` env var. OAuth `wrangler login` was avoided: the user's browser is on a remote machine, and the localhost:8976 callback is fragile over SSH tunnels.
- **Wrangler gotchas** (4.125, "Pages now part of Workers") — all baked into `auto_update.sh`:
  - The Pages project was created once via the REST API (`POST /accounts/<id>/pages/projects` with `production_branch`); `wrangler pages project create` is unreliable (it delegates to Workers and hard-fails when the auto-registered `workers.dev` subdomain is taken). No `--force` on `deploy` — the existing project deploys straight to classic Pages.
  - Run wrangler from a directory that is **not** the Next.js project (its framework detection would `npm install` @cloudflare/next-on-pages and die on the react-simple-maps/React-19 peer conflict). The local `node_modules/.bin/wrangler` is called directly (plain `npx` re-resolves against the registry and hits the same conflict).
  - `TMPDIR` is set to `~/.wrangler-tmp` (this machine's `/tmp` contains an unreadable `snap-private-tmp` dir that breaks wrangler's temp-dir discovery).
- Custom domain: Cloudflare dashboard → Workers & Pages → influenza-dashboard → Settings → Domains & Routes (CNAME `yourdomain → influenza-dashboard.pages.dev`); SSL is automatic.

## Gotchas

- **recharts 3 + React 19.2: the chart renders completely blank (no error) if `react-is` resolves to 16.x.** recharts 3.x declares `react-is` as a *peer* dep, but `prop-types` (pulled by react-simple-maps / eslint-plugin-react) hoists `react-is@16.13.1` to the root — and react-is 16's `isValidElement` rejects React 19 elements, so recharts silently drops every series child (upstream issue recharts/recharts#6857). The frontend pins it in `package.json`: `"react-is": "^19.2.3"` in dependencies **and** in `overrides` (keep both; reinstall with `--legacy-peer-deps` because of the react-simple-maps/React-19 peer conflict). If a country page ever shows an empty chart with a working legend, this is the first thing to check.
- **Public copy says "78 countries" on purpose** — it must stay consistent with the ESCAIDE abstract/citation, which say 78. The actual training set is 89 (see `training_countries.json`). Do not "fix" the dashboard copy to 89 unless the abstract and citation are updated too.
- **Site branding is "Global ILI Forecast" / "ILI Activity Dashboard", not "Influenza Forecast"** — the target is ILI/ARI case counts, not influenza-specific, so the site names the data it actually shows. The frozen ESCAIDE abstract keeps its own "influenza forecasting" wording; the two documents deliberately differ and must not be "aligned" against each other.
- Excluded from training after out-of-sample evaluation (outlier rWIS/MAPE): currently just **Thailand** (the old 12-country list is stale). The live list is in `training_countries.json` → `excluded_from_training` and is data-driven, so it can change as quality thresholds or eval results change. 89 countries are trained; 73 appear on the world map (72 countries + the UK as a single GB polygon), 14 small-island territories are country-page-only.
- `assess_data_quality.py` was deleted; its functionality is now in `prepare_finetune_data.py --assess_only`.
- Chronos-2 uses dict-based input when covariates are present: `{"target": array, "past_covariates": {...}, "future_covariates": {...}}`.
- Future covariates: `data_type`, `hemisphere`, `week_sin`, `week_cos` are passed as both past and future covariates during training and evaluation (defined in `FUTURE_KNOWN_COVARIATES` in `prepare_finetune_data.py`). Weather and neighbors are past-only.
- Weather covariates are inconsistent across countries (some have cache, some don't). Use `--weather_cache_only` in eval to avoid API rate limits.
- **WHO feed can serve object-dtype indicator columns.** The 2026-08-26 FluMart feed contained one misaligned junk row (a date string in `ARI_CASE`) that turned the whole column into object dtype, which broke the old `> 0` comparisons and made the daily cron crash at country #3 (Argentina) for every subsequent run. `extract_combined_data()` now coerces both indicator columns with `pd.to_numeric(errors="coerce")` before any numeric comparison (junk becomes NaN = missing). If a daily run ever fails in extraction, check the raw feed for non-numeric cells first.
- **Frozen model vs post-flip series.** The frozen production model was trained on the pre-flip (mostly-ILI, spliced) series for the 19 countries the parallel-reporting guard later flipped to ARI-only. Accepted mismatch: the model has seen pure-ARI countries at similar scales, and the flipped series are far more internally consistent than the mixed ones.
- `run_evaluation.py` defaults to 7 countries; pass `--countries` with a comma-separated list for all training countries, or use `--all_countries` in `run_ablation.py`. Country names with commas (e.g. "United Kingdom, England") are parsed correctly but may split incorrectly when passed via shell — the UK nations show as "not found" warnings in rolling eval.
- Training data is written to a shared `data/finetune_train.pkl` — `run_ablation.py` runs prepare→finetune sequentially per experiment, so each model trains on the correct data. But stale pickles from previous runs can cause issues if training is interrupted.
